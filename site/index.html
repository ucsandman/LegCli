Your agent hits the limit. The next one keeps your place.

Leg runs Claude Code, Codex, agy and Grok. It watches the five-hour and weekly windows, per model, and at the wall it saves the session, stops the agent, and starts the next rung of your ladder in the same terminal, from where the last one stopped. On Claude, a step down from Fable to Opus keeps the conversation itself. Every other step starts from a handoff bundle. Nothing is retyped.

npm install -g @ucsandman/legcli
pip install -U context-handoff-bundle

Then type leg claude where you would have typed claude. Same session, same flags.

Node 22 or newer. Zero runtime dependencies. $79 once, with 30 days to ask for your money back. Binds 127.0.0.1 and leaves your settings files alone.

The next option is a rung: an agent, a login, and a model.

A fresh install's ladder is claude/fable, claude/opus, claude/sonnet, then codex, then agy. Fable running out is a wall on Fable, not on your Claude login, so the first two steps down never leave it. Only when the whole login is out, or every Claude rung is, does the work go to another CLI. It is a priority list, not a rotation: put agy at the bottom and agy is the last rung from a Claude terminal and from a Codex terminal alike.

Every terminal's details print the sequence with the rung it is on, and which rung would take it right now. Hand off now on the row takes the first open rung. Hand off now to, in the details, names one, and a rung that cannot be picked says why: at its usage limit, back 11:40, shares the window that is out, buys nothing, not installed on this machine. Settings holds the default new terminals copy; Change the ladder in the details changes one terminal while it runs; leg ladder does both from a shell.

Between the warning and the wall, four things happen. You watch them.

85%

The gauge crosses its reserve notch and the terminal bell rings once. Get to a stopping point, or keep typing.

limit

Leg reads which bucket walled: one model, or the whole login. It saves the bundle it has been refreshing every two minutes, and walks the ladder from the top, naming every rung it skips and why.

stop

The agent process is stopped and the terminal is put back the way it was, down to the mouse modes and scroll margins a killed agent leaves behind, so the next rung starts on a clean line under your history.

first turn

A same-login downshift picks the conversation up mid-thought. Anything else reads .leg/RESUME.md, checks git status and git diff, and carries on with the same task.

When every rung is out

The terminal prints each option with its reset time, soonest first, then stays open with a countdown to the first reset and starts that rung from the bundle when it arrives. Ctrl-C, or End on the row, quits instead.

Climbing back

Leg never interrupts a running turn to climb. By default the higher rung is offered again at the very next hand-off, and Back to fable on the row does it now. Set climb_back to never and a terminal stays on the rung it stepped down to until you press that button.

leg claude --model opus is claude --model opus with Leg alongside. The agent's own prompt and permission flags pass through unchanged. Leg's hooks ride in a separate per-session settings file; your own settings file is never edited.

Four terminals open. One page says which one needs you.

The biggest thing on the board is a sentence: which terminal has waited on you longest, or which login your terminals are all on and how much of it is left. Under it, one strip with a token per login carrying the bucket that will actually stop the work. Each terminal is one row: what it is doing, on which model, where, how long, and the buttons that apply to it.

When Claude Code puts up a permission prompt, sits idle at the prompt, or a subagent asks for input, its Notification hook tells Leg. That row's status word becomes waiting on you with the question verbatim, it sorts to the top, the tab title reads (1) Leg with a dot on the favicon, and a toast lands in the terminal window the agent is already running in. A browser notification is there too, off until you turn it on. Codex, agy and grok publish no such signal, so their rows say quiet 4m and never claim to be waiting.

Usage is per model, not just per login, because that is how the limits fall. A row says 63% of the fable week; the strip says claude 63% 6:01 PM. A time figure appears only when the numbers earn it: three samples over ten minutes inside the current window, and then the row says about 2h 40m of Fable left, from 9 samples over 4h. Fewer samples, or a flat line, prints nothing rather than a guess.

Walk away. The terminal becomes a card. Take it back later.

A card is a terminal you are not sitting at: the same checkout, the same ladder, the same bundle at every hand-off, run headless. The End row on a terminal has two verbs. End stops the agent and keeps the bundle. End, and keep going as a card writes the bundle, hands the terminal's own worktree to a card that continues the task from the rung the terminal was on, and then ends the terminal. Nothing is cut a second time over the top of that work.

Starting one without a terminal is one field. Type the task into Run in the background under Terminals and press Start; the sentence under it says where it will run and on what, and every noun in it is a button. Build stops with the changes sitting in the worktree and merges nothing. Build and land and Factory run the tests and land on their own.

Take over on a card pauses it, writes its bundle, and hands you one command: leg claude --resume-card <id>. That opens an ordinary interactive terminal in the card's worktree, primed from its bundle. It is the one place the board hands you a command, because a browser tab cannot open a terminal, and the board says so on the line above it.

Two things a card cannot do, and the board prints both: a running card says no message until this leg ends, because the headless CLI is mute until it exits, and it never waits on a permission prompt, because its permissions are decided before it starts.

Two agents in one repo, without either one stepping on the other.

Run a second agent in a repo where one is already working and they would normally fight over the same files. Leg gives the second one its own private copy of the checkout instead, on its own branch, so both edit freely and neither sees the other's half-finished work. Two live sessions touching the same file are flagged on both rows. Nothing is merged until you say so.

Under the hood that private copy is a git worktree at .leg-worktrees/<id> on branch leg/<id>, cut from whatever branch the checkout has out. Every background card gets one the same way. If you have never used worktrees, you do not need to: Leg makes it and cleans it up.

Its row has a Land button: commit what the agent left, rebase onto the base, run the repo's tests, fast-forward the base. When a step fails nothing lands and the row says why: rebase-conflict with the files, tests-red with the end of the output, dirty-trunk when the checkout has local changes the landing would overwrite. Nothing is ever pushed.

Three more things that come with it.

Each one is a page in the docs. Here is what it does and what it does not do.

Every conversation on this machine

Claude Code, Codex, Grok, Antigravity and Copilot CLI each keep their history in their own place. leg history is one list over all of them, whether or not Leg started the conversation, and leg worktrees is one list over every checkout: git's, Leg's own, and the ones those conversations ran in. The board's Conversations count is the same index with a search box.

1,108 conversations799 claude, 198 codex, 92 agy, 14 grok, 5 copilot; looked 2m agoBrowse 1,108

Nothing moves. Leg reads those stores, writes one index file of its own, and points back. Open one and it shows the last messages and the command to continue it, where the CLI documents resume by id: Claude Code, Codex, Grok and Antigravity do; Copilot lists but cannot be continued through Leg.

Your rules, hooks and MCP servers can travel too

Off by default. leg harness enable makes a hand-off carry the working environment with the task: the source client's global rules, identity, hooks, skills, subagents, slash commands, MCP servers and permissions, rendered into the destination client's own files as far as it can represent them, with every dropped item named and explained. Skills are linked, not copied. Sources are Claude Code and Codex; destinations add agy and Gemini CLI; Grok has no adapter yet.

Every file it writes carries GENERATED by Leg harness, is backed up before an overwrite and skipped when you hand-edited it. Credentials never move: an MCP key becomes ${NAME}. The source client is never written. A policy of warn, sync or strict decides what an unattended hand-off may write.

Any CLI as a background agent

A JSON spec in ~/.leg/adapters/ makes any coding-agent CLI a card adapter, with no code in the package: leg adapter template --name muse > muse.json, leg adapter add muse.json, then --chain muse,claude. leg adapter check muse prints the exact command a leg would run before one does.

A custom adapter runs cards: headless, in a worktree, handing off like any other leg. It is not an interactive leg <agent> terminal, because that needs a usage tap and a wall signal, which only the four built-ins have. The flags that turn a supervised agent into an unsupervised one are refused whatever the spec says.

What is written, what is never touched, and what is never spent.

Subscription logins only. Leg is meant to sit beside tools you already trust, so the list of what it does not do is as exact as the list of what it does, and the same goes for the credits it will not spend without you.

Never spent without you

  • Spending is off. An automatic hand-off skips any rung that bills usage credits or a metered balance, and writes why: skipped claude/fable: it spends usage credits and you have not allowed that
  • A rung on the login that just walled account-wide is skipped as shares the window that is out, buys nothing, whatever model it names
  • A reserve per login holds a floor back from automatic hand-offs only. A hand-off you press yourself still takes it, and the picker says so on that row
  • Every rung passed over is one line in the terminal and the ledger. Nothing is skipped in silence
  • Leg never interrupts a running turn to climb back to a stronger model

Never edited

  • ~/.claude/settings.json
  • ~/.claude.json
  • ~/.codex/config.toml
  • agy's files, grok's files, and your repo's settings
  • Claude Code gets hooks through a per-session --settings file under ~/.leg; codex, agy and grok get nothing injected
  • The portable harness above is the one exception, and only after leg harness enable: marked, backed-up, Leg-owned regions, and never the source client

Written in your repo

  • .leg/, the session notes and RESUME.md
  • .context-handoffs/, the bundles
  • .leg-worktrees/, a second session's or a card's worktree, plus its leg/<id> branch
  • all three added to .git/info/exclude; landing fast-forwards your branch and nothing is pushed

Stripped and scrubbed

  • ANTHROPIC_API_KEY, ANTHROPIC_AUTH_TOKEN, ANTHROPIC_BASE_URL, ANTHROPIC_CUSTOM_HEADERS, OPENAI_API_KEY, OPENAI_BASE_URL, OPENAI_API_BASE, GEMINI_API_KEY, GOOGLE_API_KEY, GOOGLE_GEMINI_BASE_URL, GOOGLE_GENAI_USE_VERTEXAI, GOOGLE_GENAI_USE_ENTERPRISE, GOOGLE_CLOUD_PROJECT, GOOGLE_CLOUD_LOCATION, GOOGLE_APPLICATION_CREDENTIALS, CLAUDECODE, CLAUDE_CODE_*, CLAUDE_EFFORT and CLAUDE_PLUGIN_DATA are removed from every agent's environment; CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS is set to 0 for a detached Claude print session
  • Claude Code's stored login is read for the usage numbers and sent only to api.anthropic.com; it is never written or printed
  • the ledger scrubs bearer tokens and key shapes from every line; the history index caches no message body
  • the board binds 127.0.0.1; leg share on is the one way to listen elsewhere, with a token per human and, if you hand it a certificate, TLS
  • leg uninstall --yes removes ~/.leg and nothing else
